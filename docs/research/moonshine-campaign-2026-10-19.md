## First quality decision

Recommend **two measurement processes**, one per language, Small/unbiased only. Each loads once, resets session between takes, feeds 640-sample packets without pacing, and runs all corresponding existing takes plus language-matched cached guards and five-second silence/noise. This establishes native-streaming model quality and compute feasibility, not live phone latency or automatic-language product behavior. No feed/chunk/thread sweep, no new recordings. Bound every attempt in the campaign tally before launch.

Freeze exact selected files and hashes from `corpus/takes.json`, `corpus/files/benchmark/`, references `corpus/scripts/<script>.txt/.terms`, legacy D6/E6 references resolved by `tools/score.py`, and public `models/guard/refs.tsv`. Ten takes represent eight scripts. Preserve every available take, report each language separately and summarize distinct scripts separately. Original dictionary is known vocabulary: report its term subgroup and remaining words/takes separately even when unbiased; never label this unseen-name validation. Personal output/events remain in gitignored `corpus/`.

Reuse `tools/score.py` normalization, `tools/evaluate.py` scoring and Swiss `ß→ss`/`ẞ→SS` from `tools/pipeline.py:post_join`. Minimal result entries need `file`, `audioSeconds`, `text`, and honest timing/event fields; do not represent stateful input packets as independent decoded chunks. The existing variant parser has no Moonshine family. A small standalone screen is less work than modifying the frozen generic pipeline.

Existing direct-phone control counts are baseline DE/EN 46/22, FP32 dictionary 35/11, Cohere 24/23; desktop primary640 baseline EN is 22, whereas its three-feed mean differs. Verify raw report identities and recompute **primary640** controls before matching a single-feed new screen; do not compare three-feed means silently. [Evidence and scope](../archive/allocation-2026-10-19.md#quality).

Screen promotion recommendation: improve errors separately per language against matched baseline, protect meaning/required terms, no material non-vocabulary/guard regressions, and empty silence/noise. Report the existing evaluator's paired margin and tolerances as diagnostics, not an inherited FUTO or final-wait acceptance threshold. German success cannot compensate English loss. Existing FUTO observations involve different spoken takes; this stage cannot prove beating installed FUTO. Reject a clearly worse language before Android integration; allow at most one English Medium quality follow-up only if Small's actual residual errors make that worthwhile. A dictionary follow-up, if commissioned, must be matched against its own unbiased model.

Official current docs support streaming-only key terms in Python/Java: load `options={"keyterms": comma_joined_terms, "keyterm_boost": 2.0}` or `set_keyterms(list)`; default boost 2.0, false insertions rise with strength/list size. Verify the installed pinned release supports it before planning a run. No biasing is necessary for the first screen. [Mechanism and limits](https://moonshine-voice.readthedocs.io/en/latest/models/domain-customization/).

## Automatic routing and app seam, only after quality

`Engine.kt:LanguageSwitchedRecognizer` already loads Whisper-tiny, chooses DE/EN, defaults unsupported predictions to English. `tools/pipeline.py:LanguageSwitched` is its host twin. **Current timing is unsuitable:** `TakeTranscriber.submit()` calls `beginTake()` only after the first closed PauseChunker chunk. `probe_seconds` truncates that chunk; it does not make detection happen earlier. Stock Cohere uses the complete first chunk (`probe_seconds=0`, minimum chunk 20 s).

Reuse detector assets/computation and recorder buffering concepts, but add an early decision seam fed from capture start. Proposed first routing policy: one fixed two-second probe; shorter takes probe all available audio at Stop; preserve raw detection and existing English fallback. No confidence threshold is exposed by this wrapper. Buffer every opening sample while LID runs, then replay it exactly once into the selected persistent native stream and continue queued/live packets in order. Keep language fixed per take; never discard or duplicate opening audio.

Unit seams: fake detector + streaming sink with sample counters and deterministic events. Cover detection finishing between input packets, queueing during detection/replay, Stop before probe, Stop during detection, cancellation, empty/ambiguous prediction fallback, language alternation, exactly-once opening samples and final callback. Real quality follow-up must additionally inspect short/ambiguous existing audio; synthetic tests establish accounting, not language accuracy.

Record capture start, probe ready, LID wall time and chosen language, model loading, replay start/end/work, samples retained/replayed, first nonempty event, first stable completed text, Stop, final completion, peak queued audio and wrong-route/opening-word errors. Include detection/replay in complete-path CPU and wait; unpaced laptop feeding cannot establish human first-text latency. For genuine streaming during capture, paced replay or app capture must show text before Stop. Final wait alone can hide seconds of detection delay or missing openings.

App `Recognizer` exposes whole-array `transcribe()`; `TakeTranscriber` serially decodes independent closed chunks. Subclassing alone cannot make this native streaming. Preserve existing `Recorder` and `InputSession`; introduce a session sink fed directly from `TakeTranscriber.feed()` or a separate narrowly scoped streaming transcriber. Use base `Transcriber` with existing captured mono PCM, not another microphone controller. Android binding exists as `ai.moonshine:moonshine-voice`; native API/package compatibility and offline app packaging remain untested. [Android coordinates](https://moonshine-voice.readthedocs.io/en/latest/using/adding-the-library/). Download helpers add network dependencies/manifest permissions: preserve the product's offline policy when choosing packaging. [Downloader behavior](https://moonshine-voice.readthedocs.io/en/latest/using/downloading-models/).
